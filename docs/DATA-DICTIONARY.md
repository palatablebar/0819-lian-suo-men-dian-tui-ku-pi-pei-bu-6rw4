# 字段与业务定义

输入编码 UTF-8，允许 BOM。首行必须匹配样例列顺序。记录键和业务组保留原始字符串。`kind` 允许 receive, return, balance。说明列 `note` 可以跨行，限制 200 字。

业务字段按 `lot`、`day`、`expires`、`quantity` 排列。数字接受非负整数、全角数字和完整千分位。空串、短横线、N/A、NULL 与未知为缺值。无关字段用 0 占位。

退库日须早于到期日。同批号且效期一致的入库按最早入库优先，不允许引用未来入库。一单不足全单搁置并保留原余额。

`incoming.csv` 包含四个业务组，第二组提供不同边界，第三组触发业务拒收，第四组需要核对。另含重复表头、冲突记录、重复回放与错误列数。`ready.csv` 含可以签发的两个组。

## 匹配簿与签版

- `cutoff`：来源截止日，按业务字段 `day` 计；只纳入 `day <= cutoff` 的退库，也只用 `day <= cutoff` 的入库。
- 补录仓单：可用条件为 `receive.day <= return.day`，即入库日当天及之后的退库；即使早于截止点，也不能配给更早的退库。
- 退库行状态：`MATCHED`（配平）、`HELD`（搁置，整组不冲减）、`DEFERRED`（截止点之后，延后到下一签版）。
- 入库行状态：`available`（截止点内且可用）、`future`（截止点之后，本签版绝不占用）、`invalid`（仓单契约不成立）。
- 签版：`seq` 递增，`previous` 指向上一个签版；同一来源同一 `cutoff` 重放只回读既有签版。
